# Condensed lessons

> Read when something timing-, watcher-, parser- or e2e-related behaves strangely; these are mistakes already paid for.

## Condensed Lessons

- `fs.watch` unreliable on Windows — always pair with polling backup.
- Partial line buffering essential for append-only file reads (carry unterminated lines).
- Delay `agentToolDone` 300 ms to prevent React batching from hiding brief active states.
- **Idle detection** has two signals: (1) `system` + `subtype: "turn_duration"` — reliable for tool-using turns (~98%), emitted once per completed turn. (2) Text-idle timer (`TEXT_IDLE_DELAY_MS = 5 s`) — for text-only turns. Only starts when `hadToolsInTurn` is false; suppressed once `hadToolsInTurn` becomes true. Reset on new user prompt or `turn_duration`. Cancelled by ANY new JSONL data.
- User prompt `content` can be string (text) or array (tool_results) — handle both.
- `/clear` creates a NEW JSONL file (old file just stops).
- `--output-format stream-json` needs non-TTY stdin — can't use with interactive terminals.
- Hook-based IPC failed in early prototypes (hooks captured at startup, env vars don't propagate). HTTP `/api/hooks/:providerId` with `server.json` discovery (now in the office folder) works.
- PNG→SpriteData: pngjs for RGBA buffer, alpha threshold 2 (`PNG_ALPHA_THRESHOLD`), supports `#RRGGBBAA` semi-transparent pixels.
- OfficeCanvas selection changes are imperative (`editorState.selectedFurnitureUid`); must call `onEditorSelectionChange()` to trigger React re-render for toolbar.
- **External-session adoption**: scanner runs every 3 s. In hooks-OFF mode external scenarios, the test setup can race the first scanner tick. Mock-claude scenarios should give a few seconds of margin before assertions.
- **Heuristic sub-agent permission bubble timing**: the bubble lands 7 s after the SUB-TOOL is registered, not 7 s after the parent Task tool appears. Tests waiting on it from the "Subtask:" overlay need at least `1 s (Task→Bash gap) + 7 s timer + ~300 ms IPC/render = 9–10 s` budget.
- **runInBackground sub-character gate**: in webview `agentToolStart`, `runInBackground=true` Agent tools are gated out of sub-character creation when the parent has a `teamName` (teammate path handles it). With no `teamName`, the gate must be bypassed so the basic Subtask sub-character still renders. `addSubagent` dedups via `subagentIdMap`, so the bypass is safe even if a teammate is detected later. `subagentToolStart` creates the sub lazily when it's missing — covering teamed leads' unnamed background spawns and post-reload recreation.
- **Allure HTML report**: viewing via `file://` fails (browsers block `fetch()` from local files). Use `npx allure open allure-report/allure` or `npm run test:report:open`.
- **Context usage is a snapshot against a provider-declared window**, and both halves are easy to get wrong: cumulative sums measure spend rather than occupancy, `input_tokens` without the cache counters measures almost nothing, and a 200k window assumed for a 1M model reads five times too full (the number to check it against is Claude Code's own statusline `context_window.used_percentage`).
- **Typing into Claude Code through a PTY** (TYPIST-STALE, 11-04 laptop): a Windows ConPTY may hand a bracketed paste over as plain keys, so a CR inside it is Enter (the header went in as a turn of its own, the body as the next): newlines in a paste are LF (Ctrl+J, Claude Code's new line either way). An Enter can also simply not take (a composer not ready after a start, a slow paste); "no turn start seen" is not "typed": look at the box, press Enter again while it holds exactly our paste, and report `unsubmitted` otherwise.
- **A paste Claude Code checks for image paths** (T-165, 11-22: one agent's messages waited 17 hours): Claude Code 2.1.330 takes a pasted line that ends in `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp` for a dropped file. For a path that is not absolute it first reads the clipboard (on WSL through `powershell.exe`, up to 2 s), keeps the paste out of the input box meanwhile, and drops an Enter pressed in that time. So Enter goes only once the paste shows in the box (`PTY_PASTE_SHOWN_MS`), and what the box showed then is how a later look knows the paste as ours; a fixed delay before Enter and a single look at the box were not enough. The behaviour was read out of the installed binary (`grep -a -b -o -F '<fixed string>'` for the offset, then `tail -c +<offset> | head -c <n>`), not by driving the real TUI.
- **A transcript's mtime is no activity clock** (T-168, 11-22 to 11-26: no idle session was retired for four days, so every reboot woke six conversations with a prompt): the idle stop counted its 60 minutes from "the later of the first idle look and the transcript's last write". Claude Code 2.1.33x touches the transcript of a live session about an hour after the process starts (the mtime moves, the size does not, nothing is appended): five sessions started at 16:16:31 to 16:16:40 had theirs touched at 17:15:00 to 17:15:10, in start order, and evidently every hour after that (on 11-25 six sessions sat idle for eight hours without one stop; only the first touch was watched). A session the engine revives at boot ends its first turn seconds after it starts, so the touch fell seconds before the deadline, the clock started again and the stop never came. The records without a `timestamp` at the end of such a transcript (`last-prompt`, `cost-state`, `custom-title`, ...) are not that write: they appear when the process exits. We took them for it and said so in the commit that fixed this (9f327f4d7), before watching one touch happen. Nothing logs a stop that does not happen; it showed only as `orch_idle_stop` missing from the events. The clock is now the provider's own status time (`LiveSession.statusAt`): Claude's session file `statusUpdatedAt`, which it writes only together with a status (`updatedAt` moves for other fields too) and shows to its peers as a session's last activity; an ACP agent reports the last change of its own `busy`. Read in the same bundle: the status stays `busy` while a background sub-agent or workflow runs, and an ended turn with a live background shell is `shell`. When something that should happen "after N minutes of nothing" never happens, look first for what writes during the nothing, and watch it write before naming it.
