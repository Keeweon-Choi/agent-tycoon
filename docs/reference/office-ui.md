# Office UI

> Read before touching the canvas renderer, characters, sub-agent sprites, seats, bubbles, sound or UI styling rules.

## Office UI

**Rendering**: Game state in imperative `OfficeState` class (not React state). Pixel-perfect: zoom = integer device-pixels-per-sprite-pixel (1x–10x). No `ctx.scale(dpr)`. Default zoom = `Math.round(2 * devicePixelRatio)`. Z-sort all entities by Y. Pan via middle-mouse drag (`panRef`). **Camera follow**: `cameraFollowId` (separate from `selectedAgentId`) smoothly centers camera on the followed agent; set on agent click, cleared on deselection or manual pan.

**UI styling**: Pixel art aesthetic — sharp corners (`borderRadius: 0`), solid backgrounds (`#1e1e2e`), `2px solid` borders, hard offset shadows (`2px 2px 0px #0a0a14`, no blur). CSS variables in `index.css` `:root` (`--pixel-bg`, `--pixel-border`, `--pixel-accent`, ...). Pixel font: FS Pixel Sans (`webview-ui/src/fonts/`), loaded via `@font-face`, applied globally.

**Buttons, rows, lists (UI-CONSISTENCY)**: every button in a panel, window or list is `components/ui/Button.tsx` (`sm` = h-28 for rows and panels, `md` = h-32 for a dialog's main action, `icon`; one height per size, text centred, one line, 44 px on touch), never a hand-styled `<button>`. Every 설정 row is `cld/SettingRow.tsx` (title and help left, control right-aligned, `stacked` = full width under the text for three or more buttons or a field); a tab's panel sets the padding and the gap, a row never sets its own width. A list row (현황판, 팀원 popup, 스탯 view) is one line per field with `truncate` and the full text in `title`, its trailing button an `sm` Button centred on the row; the elevator's lamp, floor buttons, 편집 and 인테리어 share one width (`floors.css`).

Custom ESLint rules (`eslint-rules/agent-tycoon-rules.mjs`) enforce: `no-inline-colors` (hex/rgb/rgba/hsl/hsla literals only in `constants.ts`), `pixel-shadow` (must use `var(--pixel-shadow)` or `2px 2px 0px`), `pixel-font` (must reference FS Pixel Sans). All `error`-level — they block PRs.

**Characters**: FSM states — active (pathfind to seat, typing/reading animation by tool type), idle (wander randomly with BFS, return to seat after `wanderLimit` moves). 4-directional sprites, left = flipped right. Tool animations: typing (Write/Edit/Bash/Task) vs reading (Read/Grep/Glob/WebFetch). Sitting offset: characters shift down 6 px in TYPE state. Z-sort uses `ch.y + TILE_SIZE/2 + 0.5` so characters render in front of same-row furniture but behind lower-row furniture. **Chair z-sorting**: non-back chairs use `zY = (row+1)*TILE_SIZE` (capped to first row); back-facing chairs use `zY = (row+1)*TILE_SIZE + 1` so the chair back renders in front of the character. Chair tiles are blocked for all characters except their own assigned seat (per-character pathfinding via `withOwnSeatUnblocked`).

**Diverse palette assignment**: `pickDiversePalette()` counts palettes of current non-sub-agent characters; picks randomly from least-used palette(s). First 6 agents each get a unique skin; beyond 6, skins repeat with a random hue shift (45–315°) via `adjustSprite()`. Character stores `palette` (0-5) + `hueShift` (degrees). Sprite cache keyed by `"palette:hueShift"`.

**Spawn/despawn effect**: Matrix-style digital rain animation (0.3 s). 16 vertical columns sweep top-to-bottom with staggered timing. Spawn: green rain reveals character pixels. Despawn: character pixels consumed by green rain trails. `matrixEffect` field on Character (`'spawn'`/`'despawn'`/`null`). Normal FSM is paused during effect. Restored agents (`existingAgents`) use `skipSpawnEffect: true` to appear instantly.

**Sub-agents**: Negative IDs (from -1 down). Created on `agentToolStart` with "Subtask:" prefix, or lazily by `subagentToolStart` when missing (watched background spawns, post-reload recreation). Same palette + hueShift as parent. Click focuses parent terminal. Not persisted. Spawn at the closest free walkable tile to the parent (`closestFreeWalkableTile`) — around it, never in a seat. Idle (stop typing) when every tracked sub-tool row is done; overlay shows the latest non-done sub-tool status, falling back to the Subtask label.

**Speech bubbles**: Permission ("..." amber dots) stays until clicked/cleared. Waiting (green checkmark) auto-fades 2 s. Sprites in `spriteData.ts`.

**Sound notifications**: Ascending two-note chime (E5 → E6) via Web Audio API plays when waiting bubble appears (`agentStatus: 'waiting'`). `notificationSound.ts` manages AudioContext lifecycle; `unlockAudio()` on canvas mousedown resumes the context (webviews start suspended). Toggled via Settings modal. Persisted per-namespace in `<office folder>/config.json`.

**The owner's character (OWNER-AVATAR)**: `OfficeState.spawnOwner()` (from `useGameControls`' `ownerStep`, cld office only) puts the owner's own character (`OWNER_CHARACTER_ID`, `cldOwner`) in front of the lobby board. It lives in `characters` so it walks, rides the elevator, draws and hit-tests as agents do; the agent-only paths skip it by `cldOwner` (seats, wander, persisted seats, staff rules, chat in its menu, terminal focus). **Its 스탯 (OWNER-STATS)**: the menu's 스탯 opens `ez/OwnerStatCard.tsx` in the stats modal (`openStatDetail(OWNER_CHARACTER_ID)`): Lv, XP bar, today and total from `officeSnapshot.owner`. The daemon's `LevelStore` keeps the owner apart from agent rows (`levels.json` `owner`): XP from what a privileged `/ws` session got done (`levels.ts ownerActionOf`: a DM or room post, an allowed permission, a merge, judged by the answer; a Task added in `editTask`), and steps plus shown seconds from the page's `ownerActivity` report (`cld/ownerStats.ts`, every 30 s), clamped to the time since the last accepted report. Its Lv up plays the level-up burst like an agent's (`noteRests`). Its look is `assignments.owner` (`looks.ts ownerChoice`, the lobby counter's rule; the daemon accepts the `owner` key). Input routing is `walk.ts walkRoute`: in the free camera the keys and joystick pan; otherwise they walk the selected character, else the owner's, which the camera follows whenever nothing is selected (a cleared selection, Esc, a camera mode picked, '내 캐릭터' in the free camera or a tap on it go back to it; on another floor it first rides there by `visitFloor`). Settings → 내 캐릭터 opens its 꾸미기 and can make the 프사 from its face.

**Character moments (C1, `cld/director/`)**: `director.ts` turns a live increase of a row's 휴식 count (compaction), Lv (`level.level`) or 환생 count (renew) into a moment (`officeStore.noteRests`, through `RestWatch`: a page load or reconnect is a baseline, never a moment). Moments are small classes in `actions.ts`: a coffee break (`lounge.startBreak`: walk to the nearest coffee machine on the floor, the lounge's machine states and drinking steps, a 휴식 +1 pop, back to the desk; no machine: the drink at the mouth under a cup bubble) level-up variants A/B/C (light pillar, star orbit and nova, fireworks, 3-3.5 s, "레벨 업!" and "Lv N"; `FX_LEVELUP_LIVE` picks the live one), and C1-FX2's grand rebirths R1 ascension, R2 phoenix and R3 constellation (6-6.5 s: a charge, a burst with a flash, a lingering aura and a title entrance, over a dimmed screen with a clear disc round the figure; `FX_REBIRTH_LIVE` picks the live one). **계승 (INHERIT)**: when the owner adds an agent in a removed one's folder and ticks the add dialog's choice (`InheritChoice.tsx`, the daemon's `engineInheritable` list; the add's `inheritFrom`), the removed agent's records move to it (`projectData.inheritProjectData`: Lv/XP/환생, look, pins, inbox, Tasks, room history; it resumes the old conversation; `levels.json` `inherit` = the old count + 1). The new row's `level.inherit` going up live plays the `inherit` moment once its session's character exists (`director.ts InheritWatch`): the character's own frame again as a paled ghost beside it (`FxSpot.figure`, both renderers) hands it a mint spirit flame along an arc over linked floor rings, "계승!" stamps in with "N대째" (5.2 s, its own jingle); the StatCard tile and the 상세 스탯 list show "계승 N대째". `cld/test/run-inherit.ts` records it. One plays at a time per character (a short queue), a tap on the character skips it, prefers-reduced-motion gets a still badge, and nothing runs while nothing plays (`director.busy()` is the game loop's full-rate vote only while a moving moment plays). Back layer in the z-sort (`cldCharacterDrawables`), front layer after the whole office (`director.drawFront`), both views. Sounds are synthesized from `jingles.json` (`sounds.ts`, `playSynth` in `notificationSound.ts`, off with the sound setting). Dev trigger: open the office with `?fx=1` (a bar bottom left, and `window.__agtyFx.play(kind, id?, count?, drink?)` / `.wav(kind)`; `drink` 'energy' sends a coffee break to the vending machine); `cld/test/run-c1.ts` records the C1 mock-ups, `cld/test/run-c1-fx2.ts` the level-up and the rebirth candidates. **Drink art (C1, isometric)**: a piece may list `frames` (owner-manifest `o-coffee-machine`, `o-vending`, density 20): frame k+1 while its furniture plays "on" state k (`OfficeState.cldPantry`, the top-down office's signal; `art.ts playingFrame`), frame 0 idle, and a piece's `steam` origin steams on its last frame (`cld/steam.ts`, drawn in code). An iso8 sheet may carry a 6th row of drinking poses (coffee lifted, sip, sip eyes closed, then the same with a can): while it drinks in the three-quarter front view the renderer draws those cells (`rest.ts drinkCell`, the rest moment's lifted/sipped/lowered timeline) instead of the prop, with a held cup's steam at the preset JSON's `drinkSteam` `[{col, x, y}]` (cell px; on the wire as `CharacterPreset.drinkSteam`); `cld/test/run-c1-drink.ts` records it.

**Seats**: Derived from chair furniture. `layoutToSeats()` creates a seat at every footprint tile of every chair. Multi-tile chairs produce multiple seats keyed `uid` / `uid:1` / `uid:2`. Facing direction priority: 1) chair `orientation` from catalog (front→DOWN, back→UP, left→LEFT, right→RIGHT), 2) adjacent desk direction, 3) forward (DOWN). Click character → select (white outline) → click available seat → reassign.

**HUD windows (cld, WINMODEL)**: the desktop's floating windows (`cld/hud/HudWindow.tsx`, positions and sizes in `layout.ts`/`hudStore.ts`) follow `cld/hud/windowModel.ts`, the same model the phone's Dock tabs use. Each window is closed, front, behind or minimized, with a z order; the right icon column is a Windows taskbar: gray = closed (a press opens it in front), filled accent = in front (a press minimizes it), accent outline = open behind or minimized (a press brings it to front as it was). Only the window's × closes it; minimize and restore never reset it. 현황판 and 파일 are two icons on one window (`officeTab`). The messenger's open flag lives here too (`hud.open.messenger`). **Layers (WINDOW-LAYERS)**: `HudLayer` is one stacking context under the top bar with three bands: normal windows (z 1..n by order, the whole room, they may run under the panels), the fixed panels in its panel slot (`HUD_PANELS_Z`: the icon dock, the card bar and the elevator panel, which render there through `HudPanel`), and a maximized window (`HUD_MAXIMIZED_Z`, `windowModel.windowZ`; it fills the room under the top bar). `fixedPanels.ts` measures the `data-hud-fixed` panels (on layout changes only) and a window may go under any of them, the bottom dock row included (nothing at the bottom is reserved; the top bar is the only protected area); the one guard is `layout.keepTitleGrabbable` (at least `TITLE_GRAB_PX` of its title bar stays free). A drag is cheap: pointer moves only record a position, once per frame the window is shifted with a transform, and the place is stored once on drop (a resize renders at most once per frame). The card bar and the dock are centred in the room; the card list scrolls past `CARD_BAR_MAX_VISIBLE` cards. The desktop does not take the browser's Back for windows; full-screen overlays (the board's full view, the attachment viewer) keep their own Back entry (`overlayHistory.ts`).
