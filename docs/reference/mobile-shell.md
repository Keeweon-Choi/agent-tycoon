# Mobile shell and terminal touch rules

> Read before touching the phone shell (webview-ui/src/mobile, terminal touch, clipboard, key bar, PWA manifest).

**Mobile shell** (standalone only): below `MOBILE_MEDIA_QUERY` the browser renders `mobile/MobileShell` instead of the desktop layout — office and terminal as two full-screen pages in a 200%-wide sliding track (both always laid out, never `display:none`, so the canvas and xterm keep dimensions); the track's transform makes it the containing block of `position: fixed`, so modals and other viewport overlays mount at App's top level, never inside the office region), the agent cards in a bottom scroller, and `MobileKeyBar` above the software keyboard. "Keyboard open" and "clamp the shell" are separate answers (`mobile/keyboardViewport.ts`, sampled by `useKeyboardViewport`) because the two resize policies differ: iOS shrinks only the visual viewport (open, and the shell is clamped to it so the PTY resizes instead of hiding its input line), Android `interactive-widget=resizes-content` shrinks both (open, nothing to clamp). Open = an editable focused AND the visual viewport `KEYBOARD_MIN_HEIGHT_PX` below the tallest height seen at the current width (per-orientation baseline). Navigation rules live in `useMobileShell`: the >_ / Office toggle and the edge swipe share one handler; a card tap in the office is two-step (focus the character, then open its terminal), in the terminal it switches panes; + slides over only for launches made from it (a reload re-announcing sessions stays on the office). The terminal-pane model (active vs shown pane, socket status, `statusFor`) is `useTerminalDrawer`, shared with the desktop drawer. Touch rules: every gesture tracks ONE finger by identifier (`findTouch`) and uses one tap slop (`withinTapSlop`); gesture decisions are pure reducers with thin DOM adapters (`edgeSwipe.ts`/`useEdgeSwipe.ts`, `terminal/touchGesture.ts`/`touchInput.ts`), because WebKit keeps addressing a gesture's events to its touchstart node — when terminal rows repaint, that node detaches and events stop bubbling, so each adapter binds "rescue" listeners on the touch target. **Typed text** (Korean and every IME) goes through one layer per pane (`terminal/imeGuard.ts` rules, `imeInput.ts` DOM adapter): xterm never sees keypresses of non-ASCII characters, keydown 229, composition or input events; the hidden textarea is the one source of text and is compared with what the PTY has after each change. Text goes when it is final: at compositionend, or with no composition (Safari's Korean keyboard opens none, WebKit bug 274700) everything but a trailing Hangul syllable, which the keyboard may still rewrite; a key xterm handles, a key-bar key or a paste sends what is open first; text an IME takes back after the PTY had it becomes DELs. The open text is drawn in xterm's composition view. The layer is always on (the 설정 switch and its `agty.ime-guard` localStorage key are gone; a stored `off` is ignored). There is no separate Korean input line any more (U-33). **Terminal copy is verbatim by default** (Cmd/Ctrl+C, the browser's Copy, the pill's Copy): `flowTerminalCopy` is a heuristic that joins a long row with a two-space-indented next line, which is also what YAML under a long key or a method body under a long signature look like, so re-flowing is opt-in only — Alt+C (Option+C) on desktop, "Copy as text" on the pill. Every write goes through `terminal/clipboard.ts`. PWA: `manifest.webmanifest` (icon paths relative — the file is served verbatim), conventional-path icons in `public/`, `?v=N` cache-busters on icon links. Links (G2): `agent-tycoon/externalLinks.ts` is the one rule, installed on the browser runtime as a capture-phase click interceptor on every `<a href>`: this origin stays, another http(s) origin opens in a new window with no opener or Referer (the terminal's `terminalLinkOpener`), any other scheme is refused; programmatic opens use `openExternal`. Deliberate same-window moves to another origin (`location.assign` in the device-move flows) are not links and stay. `overscroll-behavior: none` on the page and `contain` on every scroller, `touch-action: pan-x pan-y` on the page (the canvas is `none`). The manifest has a maskable icon (`icon-maskable-512.png`, the art at 75% on its own edge colours) and the app's own `background_color`.

**Where a shell runs (T-0069, ADR-0018)**: a trusted-device shell is a terminal of our PTY host (`server/src/agent-tycoon/ptyhost/`, the process that holds the agents' PTYs), spawned with `meta: { kind: 'shell', shell: <id> }` so the engine's `claude-pty` provider never counts it as an agent (`isShellTerminal`; `/agty/attach` cannot join it either). It outlives a deploy on Linux, macOS and Windows alike: `shells.json` (0600) names each shell's host terminal, and the next daemon joins it to the host's `terminals.json`, watches it again (one subscription per shell: output is activity, its end is the shell's exit) and the panes re-attach (each viewer gets its own snapshot-then-live subscription, `ShellRegistry.join`). The daemon uses the engine's host client, or one of its own with the engine off. No tmux is installed, needed or looked for when a shell opens. A `shells.json` row without a host terminal (an older version's) is dropped at start. Without a host (a server built by a test) a shell is a plain PTY in the daemon and ends with it.

**Dock = tab bar (WINMODEL, agty)**: in the agty office the bottom Dock (`agent-tycoon/hud/MobileDock.tsx`) is a tab bar over the HUD's windows drawn as full-screen pages. The rules are one pure model, `agent-tycoon/hud/windowModel.ts` (Node-tested), shared with the desktop; `mobile/usePhoneTabs.ts` wires it to the tabs' stores and to Back. Exactly one page shows; every other page stays mounted and minimized, so it comes back as it was (conversation, scroll, draft, tab). Pressing the shown tab takes it to its root (messenger conversation → list, 현황판 → its 오케스트레이터 tab). Seven tabs (UI-DASH, owner 11-01 14:54): 사무실, 현황판, 메신저, 파일, 알림, 개발실, 터미널, 44 px each with 4 px gaps, so they fit from 360 px, each with its short name under the icon (`phoneText.dock.*`, FIX-PHONE-UI-TEXT); the old 작업실 is the 현황판's 개발 tab (오케스트레이터 · 개발; HW 탭은 11-04 에 없어져 전광판 크게 보기의 H/W 화면이 대신한다), and every link that opened it (`openWorkbench`: card buttons, notices, the 개발실's Codex link) opens that tab. There is no minimize and no close on the phone: a page's 사무실 button and the 사무실 tab go home, keeping every page. Back steps inside the tab (to its root), then home, and never closes anything else; Back and Forward never leave the app (MOBILE-SWIPE, owner 11-01 16:12, rules in `mobile/phoneHistory.ts`): from load on ONE history entry of ours (`agtyTab`) sits above the page's own, so a Back pops it, takes one step and puts it back (dropping every Forward entry); landing on it means an overlay above it was popped, landing on a closed overlay's entry (only a Forward gets there) goes back down to it. A touch starting in the outer `MOBILE_HISTORY_EDGE_PX` (16) of either side has its touchstart cancelled, which keeps iOS's history edge swipe away, unless it starts on something tappable (cancelling would eat the tap). A page back from the back/forward cache reconnects its sockets on `pageshow` (`WebSocketTransport`, `terminalClient`). A notice opens its target the same way (the messenger tab, on that conversation).

**Phone layout audit (UI-AUDIT-MOBILE)**: `agent-tycoon/test/run-ui-audit-mobile.ts` screenshots and measures every phone page and sheet at 393x852, 375x667 and 412x915 (key bar and messenger with the keyboard up, one landscape pass) and fails on horizontal overflow, an element outside the viewport, a control or text under a safe-area inset, a label cut by its box, a control label on two lines, or a tap target under 44 px. Rules it set: (1) `mobile/touchTargets.css` (base layer) makes every button, tab, summary, select, text field and checkbox row at least 44 px high and every button 44 px wide: real size, because an invisible hit area would steal the edges of neighbours in a row or a list; a strip opts out with `data-touch-compact` (only the terminal's tab strip while the keyboard is up, T-0078); a utility that sets its own `min-h-0` or `min-w-0` wins; (2) a page header carries its tabs in the title's place (the 현황판's title only repeated its selected tab); (3) the usage row (`MobileUsage` in `agent-tycoon/hud/ControlCenter.tsx`, the desktop control center's folded usage: each agent's logo, name, tightest window and what is left, on one row; a tap opens the same usage panel as a bottom sheet, FEAT-PHONE-CONTROL-CENTER, owner 11-06 19:24) is the last row of the page, above the tab bar (the tab bar is the bottom-most thing, nothing sits under it), and is left out on a phone on its side (under 500 px high, where the top bar, page header and tab bar already take half the screen); the bell and the menu stay the Dock's own; (4) while the software keyboard is up the top bar is gone, so the page pads the notch itself (`paddingTop: var(--agty-safe-top)` on the shell root; the terminal and messenger tabs sat under the status bar in a Home-Screen PWA); (5) key-bar keys are 44 px high (`MOBILE_KEY_HEIGHT_PX`); (6) a long label ends in an ellipsis (tool lines in the messenger), a Markdown table cell is at least 96 px wide and keeps Korean words whole (the table scrolls sideways in its own box), the composer's text box is as tall as its buttons.

**Walking joystick (JOYSTICK, OWNER-AVATAR)**: on the phone's office page a semi-transparent pad (`agent-tycoon/Joystick.tsx`, bottom-left of the office region, above the dock and clear of the 자동/로비 group) presses and releases the direction keys (`getWalkPad()` in `useGameControls`): they walk the selected idle character, else the owner's own character, or pan the free camera (`walk.ts walkRoute`), so there is no second movement system; `agent-tycoon/joystickMath.ts` (Node-tested) only turns a drag into one or two screen keys (8 sectors), and `walk.ts walkStepOf` makes the held keys one step in 8 directions (in the isometric view turned an eighth of a turn, so W walks up the screen; a diagonal never cuts a corner). It is shown on the office tab and view, outside the editor and the lobby, and fades to low opacity after `JOYSTICK_FADE_DELAY_MS` idle; a touch wakes it. It is its own pointer target (`touch-action: none`), so the canvas's pan and pinch are untouched outside it. Runner: `agent-tycoon/test/run-joystick.ts`.

**Roster hidden + bottom edge (ROSTER-HIDE, PHONE-CLIP)**: the hidden orchestrator strip has zero height (the office grows into it) and only a handle floats over the office's bottom edge, on the left where the strip's own toggle is (owner 11-01 03:13), under the joystick (which rests `JOYSTICK_BOTTOM_PX` = 52 up, clear of the 44 px handle) and clear of 자동/로비 (bottom-right). The bottom inset is counted once, by the bottom-most band (`mobile-bottom` pads `max(4px, --agty-safe-bottom)`). A Home-Screen app whose layout viewport is short of the screen by the top inset (seen on an iPhone 12/13, 797 of 844 px) gets a band under the page that **nothing can be laid out into**: WebKit paints no box past the layout viewport there, only the document's background, and iOS pans the page above the keyboard no further than that viewport's bottom. Stretching `#root` past it (11-01 02:49) cut the Dock's icons in half and left the composer's last 47 px under the keyboard. So `useStandaloneViewport` (`mobile/standaloneViewport.ts` holds the rule) gives that band the Dock's colour (`html` background) and drops the bottom inset inside the viewport (`--agty-safe-bottom` minus the shortfall: the home indicator is in the band). On that iPhone, with the keyboard up, `innerHeight` reads the same 477 px as `visualViewport.height` (the composer's height showed it), so the shell is not clamped and iOS's pan brings the composer up. Runners: `agent-tycoon/test/run-phone-clip.ts` (WebKit: installed app short and full, Safari tab; Chromium Android; office, roster toggle in its three states, composer with and without the emulated keyboard) and `agent-tycoon/test/run-mobile-dock.ts` (iPhone inset 34, SE 0, Galaxy gesture 16 and 3-button 0, and the short viewport).

**Phone office fixes (UI-PHONE, audit 11-01)**: (1) in the 2D office with the real camera (자동) the phone's first view frames the rooms where agents work on the current floor (`workRoomsBox` in `agent-tycoon/camera.ts`, never farther than the floor's own framing), waiting up to `PHONE_ISO_SETTLE_S` for one to show up; only with nobody at work does it follow the owner's character. The 자동 / 내 캐릭터 / 로비 group is a covered strip for that framing (`data-hud-fixed` on the phone), and the lobby board's wall copy shows two columns, name and state, laid in the part of the board on screen (`.led-phone`, `--led-vis-l` / `--led-vis-w` from `LobbyBoard`). Runner: `agent-tycoon/test/run-phone-zoom.ts` (its `phone-2d-auto` step).
(2) An agent's summary card on the phone carries its menu (대화 / 꾸미기 / 스탯) as its own bottom row (`CharacterMenuItems` in `agent-tycoon/characters/CharacterMenu.tsx`; the floating menu under the feet stays for the owner's character and the desktop), and while it is open every other plate is drawn at `PHONE_CARD_OTHERS_ALPHA`. Runner: `agent-tycoon/test/run-stat-card.ts`.
(3) The DM composer on touch keeps the text box and 보내기 on one row; 첨부 and 즉시 보내기 (with their icons, the latter's title says it goes in even while the agent works) sit on a row under it, and a queued message's 지금 보내기 / 수정 / 취소 are small buttons on a row of their own (44 px on touch). The group room's composer is its own (`messenger/rooms/`).

**Messenger head on the phone (FIX-PHONE-MESSENGER-HEADER, owner 11-06 21:42)**: the conversation head is a grid (`.msg-head-phone`, only when `useIsMobile`; the desktop head keeps its flex-wrap row): the portrait spans two rows, the four buttons (search, list, grid, terminal) sit right-aligned in the name's row at 40 px (`.msg-head-tools` is `data-touch-compact`, so the 44 px floor of `touchTargets.css` and the audit's 44 px check are lifted for this group on purpose: 40 is the owner's size), the name truncates before it pushes them, and the state line under it runs to the right edge. The usage row says what the number is, "남음" (`controlCenter.left`, the gauge's word): the figure is `leftPct`, the share left. Runner: `agent-tycoon/test/run-fix-phone-messenger-header.ts` (WebKit 390x844 in both styles, Chromium 1600x1000).

**Notifications page on the phone (FIX-PHONE-NOTICES-COMPACT, T-68, owner 11-06 22:33)**: `notify/NoticePhonePage.tsx` is the page (the App mounts it in place of a bare `MobilePage`): its head row is the page's own, title, the bell with where things stand (`NoticeStatus`: "모두 확인했어요" or the unread count), 설정 (`NoticeViewToggle`) and 사무실, one row down to 375 px (the status gives way with an ellipsis first). The panel passes `phone` to `NoticeCenter`, which then draws one filter button (its label is the picked category's name, with a dot while anything narrows the list: a category, a facet, a search or the sort) and the list under it; the category tabs, the search, the sort and the facet chips are one bottom sheet (`.nc-sheet`, absolute inside `.nc-phone`, so the page's transform does not matter) opened by that button. Only the phone passes `phone`: the desktop panel, even in its narrow 420 px window, keeps its markup (the before/after HTML of `run-fix-phone-notices-compact.ts` is byte-identical). Runner: `agent-tycoon/test/run-fix-phone-notices-compact.ts` (WebKit 390x844 and 375x667 in both styles, Chromium 1600x1000).
