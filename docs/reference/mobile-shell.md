# Mobile shell and terminal touch rules

> Read before touching the phone shell (webview-ui/src/mobile, terminal touch, clipboard, key bar, PWA manifest).

**Mobile shell** (standalone only): below `MOBILE_MEDIA_QUERY` the browser renders `mobile/MobileShell` instead of the desktop layout — office and terminal as two full-screen pages in a 200%-wide sliding track (both always laid out, never `display:none`, so the canvas and xterm keep dimensions); the track's transform makes it the containing block of `position: fixed`, so modals and other viewport overlays mount at App's top level, never inside the office region), the agent cards in a bottom scroller, and `MobileKeyBar` above the software keyboard. "Keyboard open" and "clamp the shell" are separate answers (`mobile/keyboardViewport.ts`, sampled by `useKeyboardViewport`) because the two resize policies differ: iOS shrinks only the visual viewport (open, and the shell is clamped to it so the PTY resizes instead of hiding its input line), Android `interactive-widget=resizes-content` shrinks both (open, nothing to clamp). Open = an editable focused AND the visual viewport `KEYBOARD_MIN_HEIGHT_PX` below the tallest height seen at the current width (per-orientation baseline). `useIsMobile` is gated on `isBrowserRuntime`: a narrow VS Code panel must never get it (it broke every VS Code e2e shard once). Navigation rules live in `useMobileShell`: the >_ / Office toggle and the edge swipe share one handler; a card tap in the office is two-step (focus the character, then open its terminal), in the terminal it switches panes; + slides over only for launches made from it (a reload re-announcing sessions stays on the office). The terminal-pane model (active vs shown pane, socket status, `statusFor`) is `useTerminalDrawer`, shared with the desktop drawer. Touch rules: every gesture tracks ONE finger by identifier (`findTouch`) and uses one tap slop (`withinTapSlop`); gesture decisions are pure reducers with thin DOM adapters (`edgeSwipe.ts`/`useEdgeSwipe.ts`, `terminal/touchGesture.ts`/`touchInput.ts`), because WebKit keeps addressing a gesture's events to its touchstart node — when terminal rows repaint, that node detaches and events stop bubbling, so each adapter binds "rescue" listeners on the touch target. **Typed text** (Korean and every IME) goes through one layer per pane (`terminal/imeGuard.ts` rules, `imeInput.ts` DOM adapter): xterm never sees keypresses of non-ASCII characters, keydown 229, composition or input events; the hidden textarea is the one source of text and is compared with what the PTY has after each change. Text goes when it is final: at compositionend, or with no composition (Safari's Korean keyboard opens none, WebKit bug 274700) everything but a trailing Hangul syllable, which the keyboard may still rewrite; a key xterm handles, a key-bar key or a paste sends what is open first; text an IME takes back after the PTY had it becomes DELs. The open text is drawn in xterm's composition view. `localStorage['cld.ime-guard']='off'` falls back to xterm's own path. There is no separate Korean input line any more (U-33). **Terminal copy is verbatim by default** (Cmd/Ctrl+C, the browser's Copy, the pill's Copy): `flowTerminalCopy` is a heuristic that joins a long row with a two-space-indented next line, which is also what YAML under a long key or a method body under a long signature look like, so re-flowing is opt-in only — Alt+C (Option+C) on desktop, "Copy as text" on the pill. Every write goes through `terminal/clipboard.ts`. PWA: `manifest.webmanifest` (icon paths relative — the file is served verbatim), conventional-path icons in `public/`, `?v=N` cache-busters on icon links. Links (G2): `cld/externalLinks.ts` is the one rule, installed on the browser runtime as a capture-phase click interceptor on every `<a href>`: this origin stays, another http(s) origin opens in a new window with no opener or Referer (the terminal's `terminalLinkOpener`), any other scheme is refused; programmatic opens use `openExternal`. Deliberate same-window moves to another origin (`location.assign` in the device-move flows) are not links and stay. `overscroll-behavior: none` on the page and `contain` on every scroller, `touch-action: pan-x pan-y` on the page (the canvas is `none`). The manifest has a maskable icon (`icon-maskable-512.png`, the art at 75% on its own edge colours) and the app's own `background_color`.

**Dock = tab bar (WINMODEL, cld)**: in the cld office the bottom Dock (`cld/hud/MobileDock.tsx`) is a tab bar over the HUD's windows drawn as full-screen pages. The rules are one pure model, `cld/hud/windowModel.ts` (Node-tested), shared with the desktop; `mobile/usePhoneTabs.ts` wires it to the tabs' stores and to Back. Exactly one page shows; every other page stays mounted and minimized, so it comes back as it was (conversation, scroll, draft, tab). Pressing the shown tab takes it to its root (messenger conversation → list, 작업실 → its first tab, 현황판 → its own tab). There is no minimize and no close on the phone: a page's 사무실 button and the 사무실 tab go home, keeping every page. Back steps inside the tab (to its root), then home, and never closes anything else: while the phone is away from home ONE history entry of ours (`cldTab`) sits on top, re-pushed after a step that stays away; landing on it means an overlay above it was popped. A notice opens its target the same way (the messenger tab, on that conversation).

**Phone layout audit (UI-AUDIT-MOBILE)**: `cld/test/run-ui-audit-mobile.ts` screenshots and measures every phone page and sheet at 393x852, 375x667 and 412x915 (key bar and messenger with the keyboard up, one landscape pass) and fails on horizontal overflow, an element outside the viewport, a control or text under a safe-area inset, a label cut by its box, a control label on two lines, or a tap target under 44 px. Rules it set: (1) `mobile/touchTargets.css` (base layer) makes every button, tab, summary, select, text field and checkbox row at least 44 px high and every button 44 px wide: real size, because an invisible hit area would steal the edges of neighbours in a row or a list; a strip opts out with `data-touch-compact` (only the terminal's tab strip while the keyboard is up, T-0078); a utility that sets its own `min-h-0` or `min-w-0` wins; (2) a page header carries its tabs in the title's place (the 현황판's title only repeated its selected tab); (3) the usage line is the last row of the page, above the tab bar (the tab bar is the bottom-most thing, nothing sits under it), and is left out on a phone on its side (under 500 px high, where the top bar, page header and tab bar already take half the screen); (4) while the software keyboard is up the top bar is gone, so the page pads the notch itself (`paddingTop: var(--cld-safe-top)` on the shell root; the terminal and messenger tabs sat under the status bar in a Home-Screen PWA); (5) key-bar keys are 44 px high (`MOBILE_KEY_HEIGHT_PX`); (6) a long label ends in an ellipsis (tool lines in the messenger), a Markdown table cell is at least 96 px wide and keeps Korean words whole (the table scrolls sideways in its own box), the composer's text box is as tall as its buttons.
